Quickstart

Installation & Quickstart

Use RustyGraph as an embedded library inside your Rust application, or run it as a standalone NoSQL server daemon with multi-threaded REST and interactive CLI clients.

Cargo.toml 
[dependencies]
rusty_graph = { git = "https://github.com/maheshwarLigade/rustygraph.git" }
main.rs 
use rusty_graph::prelude::*;

fn main() -> Result<()> {
    let mut graph = Graph::new();

    // 1. Create nodes with labels and rich properties
    let alice = graph.create_node_with(|n| {
        n.add_label("Person");
        n.set_prop("name", "Alice");
        n.set_prop("age", 30);
    })?;

    let bob = graph.create_node_with(|n| {
        n.add_label("Person");
        n.set_prop("name", "Bob");
        n.set_prop("age", 28);
    })?;

    // 2. Create directed relationship
    graph.create_edge_with(alice, bob, "KNOWS", |r| {
        r.set_prop("since", 2021);
    })?;

    // 3. Execute native openCypher query!
    let res = graph.cypher("MATCH (p:Person)-[:KNOWS]->(f:Person) WHERE f.age < 30 RETURN p.name, f.name")?;
    println!("Found {} friend connection(s)", res.rows.len());

    Ok(())
}

Native Go SDK using dynamic linking with 0 CGO overhead:

Go 
package main

import (
    "fmt"
    "github.com/mahesh/rusty-graph/bindings/go/rustygraph"
)

func main() {
    client, err := rustygraph.NewClient("./librusty_graph.so")
    if err != nil { panic(err) }
    defer client.Close()

    g, _ := client.CreateGraph()
    defer g.Free()

    alice, _ := g.CreateNode("Person", `{"name": "Alice", "age": 30}`)
    bob, _ := g.CreateNode("Person", `{"name": "Bob", "age": 28}`)
    g.CreateEdge(alice, bob, "KNOWS", `{"since": 2021}`)

    res, _ := g.Cypher("MATCH (a:Person)-[:KNOWS]->(b:Person) RETURN a.name, b.name")
    fmt.Println(res)
}

Modern Java 21+ SDK utilizing Project Panama Foreign Function & Memory (FFM) API:

Java 21 
import com.rustygraph.RustyGraph;

public class App {
    public static void main(String[] args) {
        try (var graph = RustyGraph.open()) {
            long u1 = graph.createNode("User", "{\"name\": \"Alice\"}");
            long u2 = graph.createNode("User", "{\"name\": \"Bob\"}");
            graph.createEdge(u1, u2, "FOLLOWS", "{\"since\": 2024}");

            String cypherJson = graph.cypher("MATCH (a:User)-[:FOLLOWS]->(b:User) RETURN a.name, b.name");
            System.out.println(cypherJson);
        }
    }
}

Architecture

Generational Arena & Memory Model

RustyGraph avoids raw pointers and traditional graph garbage collection by implementing a contiguous generational slot arena with dense 64-bit identifiers.

⚡

Generational SlotArena

Every node and relationship ID encodes an index and generation counter. Slot reuse is 100% memory-safe, completely preventing ABA problems and use-after-free bugs.

📦

Inline SmallVec Adjacency

Each node stores incoming and outgoing relationship IDs in inline stack-allocated SmallVec<[RelId; 8]>. Nodes with degree ≤ 8 allocate zero heap memory during traversal.

💎

Algebraic Property Values

Rich enum system supporting Null, Bool, Int, Float, String, Bytes, DateTime, List, and Map with total ordering and JSON serde.

💡
Pointer-Free Graph Safety

In standard graph database implementations, circular references cause pointer chasing and memory fragmentation. RustyGraph's generational arena enables $O(1)$ indexed dereferencing with zero pointer dereference hazards.

Query Engine

openCypher Language & Mutations

RustyGraph includes a complete openCypher lexer, parser, and AST execution engine supporting both declarative reading and ACID mutations.

Clause / Feature Syntax Example Behavior
MATCH MATCH (a:User)-[:KNOWS]->(b:User) Pattern matching across directed, incoming, or undirected graph relationships.
WHERE WHERE u.age >= 21 AND u.status = 'active' Supports comparison operators (=, !=, <, <=, >, >=) and logical AND.
CREATE CREATE (n:Person {name: 'Alice'})-[:FOLLOWS]->(m:Person {name: 'Bob'}) Creates nodes and directed edges atomically in memory and persists to WAL.
SET MATCH (p:Person {name: 'Alice'}) SET p.age = 31 Mutates properties on all matched node entities.
DELETE MATCH (p:Person {name: 'Alice'}) DELETE p Strict node deletion; fails if node has connected relationships.
DETACH DELETE MATCH (p:Person {name: 'Alice'}) DETACH DELETE p Cascading deletion; removes incident relationships, indexes, and vector embeddings.
Aggregations RETURN count(*), sum(p.price), avg(p.price), min(p.price), max(p.price) Full columnar aggregation calculations across matched query context.
ORDER BY / LIMIT ORDER BY p.price DESC LIMIT 10 Sorts result rows ascending or descending with pagination limit.
ACID Guarantees

Multi-Statement ACID Transactions

Execute transactional workloads with complete snapshot isolation. Staged writes remain private until commit, where they are atomically written to the Write-Ahead Log and applied to the live graph.

🛡️

Snapshot Isolation

Every transaction receives a private, isolated copy of the graph. Dirty reads are strictly impossible for concurrent clients.

💾

WAL Durability & CRC32

Committed transactions append atomic records verified with IEEE 802.3 CRC32 checksums. Automatic crash replay restores exact state upon reboot.

⏱️

Timeout & Background Reaper

Transactions specify a maximum TTL (e.g. 30s). Abandoned or hung transactions are automatically aborted and reclaimed.

Rust Transaction Example 
// 1. Begin multi-statement transaction with 15s timeout
let tx_id = db.begin_transaction(Some(Duration::from_secs(15)))?;

// 2. Stage multiple mutations inside transaction
db.execute_tx(tx_id, "CREATE (u:User {name: 'Alice', balance: 500})")?;
db.execute_tx(tx_id, "CREATE (u:User {name: 'Bob', balance: 200})")?;
db.execute_tx(tx_id, "MATCH (u:User {name: 'Alice'}) SET u.balance = 400")?;

// Live database queries see 0 new users (Complete Isolation!)
let live_view = db.cypher("MATCH (u:User) RETURN u.name")?;
assert_eq!(live_view.rows.len(), 0);

// 3. Atomically commit to WAL and live database
db.commit_transaction(tx_id)?;

// Live database now reflects committed users
let committed_view = db.cypher("MATCH (u:User) RETURN u.name")?;
assert_eq!(committed_view.rows.len(), 2);

AI & Search

Vector Database & Relational GraphRAG

Seamlessly combine dense semantic vector embeddings with relational graph context for next-generation LLM retrieval.

GraphRAG Example 
// 1. Create a Vector Index on 'Paper' node embeddings using Cosine similarity
graph.create_vector_index(
    "paper_embeddings",
    "Paper",
    "embedding",
    4, // 4-dimensional vectors
    VectorSimilarity::Cosine,
)?;

// 2. Hybrid GraphRAG: Find top 2 nearest papers and expand 2 hops into citations & authors
let query_vector = vec![0.75, 0.80, 0.85, 0.30];
let rag_results = graph.vector_search_and_traverse(
    "paper_embeddings",
    &query_vector,
    2, // top 2 seed documents
    2, // expand 2 relational hops
)?;

for (hit, paths) in rag_results {
    println!("Seed Document {} (Score: {:.4})", hit.node_id, hit.score);
    for path in paths {
        println!("  Subgraph context: {}", path);
    }
}

REST API Reference

The standalone daemon (rustygraph-server) exposes high-throughput JSON endpoints for Cypher, transactions, and administration.

Method Endpoint Description Payload

POST /tx/begin Start multi-statement ACID transaction {"timeout_ms": 30000}
POST /tx/:id/cypher Execute Cypher inside active transaction {"query": "CREATE (u:User {name: 'Neo'})"}
POST /tx/:id/commit Commit transaction to WAL and live database none
POST /tx/:id/rollback Rollback transaction, discarding staged changes none
GET /tx/list List active transactions and remaining TTLs none
GET /stats Retrieve nodes, edges, and WAL sequence metrics none
POST /vector/search Top-k nearest neighbor vector search {"index": "v", "k": 5, "vector": [...]}
POST /checkpoint Trigger immediate snapshot & WAL truncation none
GET /cluster/status Cluster consensus state, leader, and peer nodes none
Clustering

Distributed Clustering & CAP Theorem

RustyGraph provides configurable distributed consensus guarantees tailored to your consistency or availability requirements:

⚖️

CP Mode (Consistency)

Strict majority quorum writes (> N/2), term tracking, leader election, and automated write rejection on minority partitions to prevent split-brain.

⚡

AP Mode (High Availability)

100% write availability across all partitions with Lamport logical timestamps and anti-entropy Last-Write-Wins (LWW) reconciliation upon healing.
